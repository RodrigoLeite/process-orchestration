Você é um engenheiro de software sênior responsável por corrigir toda a arquitetura de workflows do meu SaaS.  
O sistema foi implementado errado: ele está usando um único workflow por área, mas a lógica correta é Workflow Por Demanda com Deduplicação Inteligente.

Abaixo está a especificação detalhada CORRETA que você deve implementar ou ajustar no código existente.

====================================================================
🧠 1. VISÃO CORRETA DO PRODUTO
====================================================================

Cada demanda deve gerar seus próprios steps, criados pela IA.  
O sistema deve:

1. Receber os steps gerados pela IA para aquela demanda  
2. Criar um hash único baseado na estrutura do workflow
3. Verificar se já existe workflow IDÊNTICO no banco  
4. Se existir ➜ reutilizar  
5. Se não existir ➜ criar novo  
6. Associar a demanda ao workflow encontrado/criado  
7. Kanban deve mostrar SOMENTE as etapas daquele workflow  
8. NUNCA usar workflow por área. Apenas workflows por demanda.

====================================================================
🧠 2. DEFINIÇÃO DE "WORKFLOW IGUAL"
====================================================================

Dois workflows são iguais se:

- possuem o mesmo número de steps  
- steps estão na mesma ordem  
- cada step possui exatamente:
  * nome
  * tipo
  * descrição
  * prioridade
  * responsável
  * dependências  
  * critérios de aceitação  
  * duração (em horas/dias)

O sistema deve gerar um HASH baseado no JSON canonicalizado dos steps.

====================================================================
🧠 3. MODELO DE DADOS (Drizzle)
====================================================================

Ajuste/valide as seguintes tabelas:

TABLE workflows  
- id (pk)  
- areaId (opcional)  
- workflowHash (unique)  
- createdAt  

TABLE workflowSteps  
- id (pk)

- name

TABLE demands

- areaId (fk)
- workflowId (fk)
- createdAt

====================================================================
🧠 4. FLUXO CORRETO DO BACKEND
====================================================================

Quando uma nova demanda é criada:

1. O agente gera steps em JSON
2. Normalizar JSON (ordenar keys, remover caracteres desnecessários)
3. Gerar hash SHA-256 dos steps
4. Consultar tabela workflows WHERE workflowHash = hash
5. Se existir:
     - workflowId = existente
   Se não existir:
     - criar workflow
     - criar steps
     - salvar hash
6. Atualizar demanda.workflowId = workflowId
7. Retornar demanda + workflow + steps

🧠 8. REGRAS DE HASH
====================================================================

Função hash(workflowSteps):
  - converter steps em JSON canonicalizado
  - ordenar por `order`
  - serializar com ordenação de keys
  - gerar SHA-256
  - salvar em workflow.workflowHash
